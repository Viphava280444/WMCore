# WMCore CI - KNOWN FAILING TESTS MANIFEST
#
# WHAT THIS FILE IS
#   Every unit test that is currently expected to fail on BOTH master and any PR,
#   with the family it belongs to, why it fails, and what would fix it.
#   It EXPLAINS failures. It does NOT forgive anything.
#
# WHAT DECIDES THE GATE (this file has no vote)
#   The PR gate is a diff against the newest successful master baseline run.
#   A test turns the gate red only when it PASSES on the baseline and FAILS on the PR.
#   A test that fails identically on both sides never enters any diff bucket and is
#   silently forgiven by the comparison itself - that is what this file documents.
#   test/etc/UnstableTests.txt is a DIFFERENT list: it forgives baseline->PR status
#   FLIPS for non-deterministic tests. A test can be in both files, in either, or
#   in neither. Adding a test here can never make a red run green.
#
# WHO READS IT
#   The "Write run summary" step of .github/workflows/wmcore-pr-test.yml renders the
#   families table in the GitHub Actions run summary from this file, and shouts about
#   any failing test that appears in NEITHER this file NOR UnstableTests.txt.
#
# FORMAT (plain text, pipe-delimited, python3 stdlib parseable)
#   [families]  slug | fix-class | one-line reason | fix path
#   [tests]     classname:testMethod | family-slug
#   [skips]     classname:testMethod | skip-class
#   The key is the nose-collected classname exactly as recorded in the result
#   XML - often NOT fully qualified (e.g. MSUnmerged_t.MSUnmergedTest:testCutPath,
#   Api_t.Tester:test_multi_throw5b). Copy it from the XML or from the summary page.
#   '#' starts a comment. Fields are stripped. No pipes inside a field.
#
#   fix-class is who has to act:
#     test-fix          change only test code
#     test-infra-fix    change shared test harness under src/python/WMQuality
#     test-harness-fix  change the nose/webtest bootstrap, not a single test
#     product+test-fix  a real src/python product bug is part of it
#     ci-config         the CI stack/compose/env is wrong, not the code
#     admin-request     someone outside this repo must grant something
#     flaky             non-deterministic; also listed in UnstableTests.txt
#
# MAINTENANCE
#   New pre-existing failure appears  -> the run summary prints it under
#                                        "UNEXPLAINED - investigate". Triage it, then
#                                        add one [tests] line (and a [families] row if
#                                        it is a new cause) in the same PR.
#   A known failure gets fixed        -> the run summary prints it under
#                                        "FIXED - remove from manifest". Delete its
#                                        [tests] line in the PR that fixed it.
#   Never delete a line to quiet the summary. Deleting a line for a still-failing test
#   moves it straight into the loud UNEXPLAINED section.
#
# Counts as of baseline run 32377920419 / acceptance run 32399324762 (2026-08-18):
#   1653 tests, 29 failures, 36 errors, 14 skipped -> 65 failing, all listed below.
#   63 of them fail identically on the baseline; 2 (flaky-workqueue) passed on the
#   baseline and were forgiven as unstable flips.
